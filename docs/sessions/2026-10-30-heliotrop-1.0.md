# 2026-10-30: Heliotrop 1.0

kind: build

## Scope

Redesign of the `stack` engine (0.8.0, a prototype with one slice-shaped workflow for every session) into Heliotrop
1.0. Out of scope: restoring session metrics and the session doctor.

## Done

- Read-only audit of the 0.x engine against the diagnostics reports (now in the git history): main-session context
  peaked at a median of ~157k over 30 sessions, 6 sessions passed 200k and two ended because the orchestrator's
  context ran out; one off-topic stretch cost ~37% of a session's main-thread spend; research and documentation
  sessions fit the slice workflow badly.
- Spec: [design/heliotrop-1.0.md](../design/heliotrop-1.0.md).
- Implementation by subagents from the spec, in four groups with disjoint files: hooks, orchestrator rules, skills,
  rename and repository; `plugins/heliotrop/`, [CHANGELOG.md](../../CHANGELOG.md) (1.0.0), [README.md](../../README.md).
- Scope of 1.0.0: rename; soft session kinds; triage of off-topic messages; explaining consequences; main-context
  points (150k notice, 200k hard point); 5-minute prompt-cache notice; standard document set and optional engine
  templates; light mode without a contract; `init` with documentation audit, migration from 0.x, git/GitHub check and
  a short setup Q&A; new skills `handover` and `guide`; the engine repository's own contract
  ([.claude/project.md](../../.claude/project.md)); metrics and the session doctor removed, archive hook kept.
- Engine repository documents started: [decisions.md](../decisions.md) (entries before 2026-10-30 reconstructed from
  commits), [roadmap.md](../roadmap.md).
- Checks: `node tests/hooks/test.js` passes. A review ran before commit; its results are recorded separately.

## Decisions

- `kind: design → build` — the audit's conclusions were approved and implemented in the same session.
- Lasting decisions of this session are in [decisions.md](../decisions.md), entries dated 2026-10-30.
- `init` setup Q&A asks only about tests, review, commits and optional documents; every other contract setting starts
  from the engine default.
- The main session's prompt-cache TTL is a user setting (`"promptCacheTtl": "1h"`); the plugin only reports a 5-minute
  write — a plugin cannot set it.
